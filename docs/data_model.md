# 当前调用身份

正在操作的用户信息

| 字段名 | 类型 | 业务含义 | 来源 | 约束 |
|---|---|---|---|---|
| `current_user_id` | 字符串 | 当前可信调用身份 | 测试环境，后续由可信会话提供 | 不能由模型任意指定其他身份 |

# 订单行

订单中具体的一种商品和数量

| 字段名 | 类型 | 业务含义 | 来源 | 约束 |
|---|---|---|---|---|
| `order_id` | 整数 | 所属订单的唯一标识 | 测试数据提供 | 不同订单标识不同；同一订单的多个商品行共享此值 |
| `owner_id` | 字符串 | 订单所属的用户 id | 订单创建时获取创建者 id | 只有与 current_user_id 相同时，才允许操作；不同时拒绝 | 
| `product_name` | 字符串 | 商品名称 | 订单创建时获取 | 暂无 |
| `days_since_delivery` | 整数 | 收货后经过的完整天数 | 从收货时刻至当前已经过去的完整天数；今天由测试数据直接提供，暂不实现日期换算 | 已收货时为非负整数；演示规则允许 0～14 天申请 |
| `purchased_qty` | 整数 | 购买的总数量 | 确认订单时确认 | 正整数 |
| `reserved_qty` | 整数 | 已成功申请退货的数量 | 退货申请提交成功后累加 | 整数，0 ≤ reserved_qty ≤ purchased_qty；申请提交成功后增加 |
| `returnable` | 布尔值 | 商品属性是否允许申请退货 | 由商品属性决定 | 不是最终能否退货的结论，最终仍要结合身份、状态、期限和数量判断 |
| `order_line_id` | 整数 | 订单行的稳定唯一标识 | 测试数据提供 | 全局唯一，不随显示位置或排序改变 |
| `status` | 布尔值 | 表示是否收货 | 订单确认收货后改为 true | true 表示已收货，false 表示未收货 |

# 本次申请输入

澄清并匹配订单后，交给校验逻辑的结构化申请输入

| 字段名 | 类型 | 业务含义 | 来源 | 约束 |
|---|---|---|---|---|
| `order_line_id` | 整数 | Agent 根据用户描述查询并澄清后，从订单数据中取得；必须对应当前用户的实际订单行 | 在会话中根据用户找到对应订单后确定商品在订单中的识别码 | 必须的字段 |
| `quantity` | 整数 | 本次申请的退货数量 | 用户输入 | 正整数，不接受布尔值；quantity ≤ purchased_qty - reserved_qty |
