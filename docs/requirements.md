# 用户与目标

这个项目是一个处理用户退货行为的 agent，用户可以通过该 agent 来判断对应商品能否退货并让 agent 生成退货申请，交给用户确认后再提交。

# 输入与结果

用户输入退货需求，agent 澄清获取商品名称和退货数量，获取用户的历史订单信息，判断退货请求能否执行，不能执行直接返回对应的失败，能执行则制作退货申请，交给用户确认后提交。

# 范围

产品最小版本：接入 agent，完成澄清、查询、预览、确认和提交的完整功能。

# 职责分配

Agent 负责：理解用户目的，判断当前信息是否足够、是否需要继续问，选择查询工具并根据查询结果决定下一步，解释结果、提出申请方案。
代码负责：提供可信身份、订单和规则，检查权限、数量和业务条件，执行受约束的工具操作，校验确认、控制重试、保证提交不重复。

# 验收依据

- 信息不足时，先澄清，不直接提交
- 对超出退货职责范围的请求，说明不支持，不执行相应操作
- 用户确认申请方案后，才允许尝试提交
- 申请提交成功后，新增对应申请，并占用相应可退货数量；提交失败不得留下有效申请和数量占用
- 查询、澄清和预览不会改变订单和申请的业务状态；不得修改无关业务数据

# 约束

商品或数量变化后，旧确认失效，需要重新确认最新方案。不能把“确认过一次”当作后续操作的通行证。
“不符合退货规则”和“查询工具超时”不能都归为退货失败。前者可以给出业务判断，后者只能说明暂时无法判断，不能编造结论。
